# Mailhere Android — geliştirme ve sürüm

Bu belge Android kabuğunun kurulumunu, mimarisini, sürüm şemasını ve cihazda denetlenecekleri anlatır. Tasarım ve güvenlik kuralları için alt modüldeki `docs/TASARIM.md` (§12 Mobil uyarlama) ve `docs/GUVENLIK.md` ("Android") geçerlidir.

## 1. Kurulum

Gerekenler:

| Araç | Sürüm | Not |
| --- | --- | --- |
| Rust (stable) | ≥ 1.90 | `rustup target add aarch64-linux-android` |
| Android SDK | platforms `android-36`, build-tools `36.0.0`, cmdline-tools | `sdkmanager --install "platforms;android-36" "build-tools;36.0.0"` |
| Android NDK | **28.2.13676358** | `sdkmanager --install "ndk;28.2.13676358"`; CI aynı sürümü kullanır |
| Java | 21 (Temurin) | Gradle 9 ve AGP 9 için |
| Node | 22 · pnpm 10 | `corepack enable` |

Ortam değişkenleri (kabuk profiline):

```bash
export ANDROID_HOME=/opt/android-sdk                        # kendi yolun
export NDK_HOME=$ANDROID_HOME/ndk/28.2.13676358
export ANDROID_NDK_HOME=$NDK_HOME
# SQLCipher'in OpenSSL'i kaynaktan derlenir (openssl-src); cc ve openssl-src NDK'nın clang'ını ister.
BIN=$NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/bin
export CC_aarch64_linux_android=$BIN/aarch64-linux-android24-clang
export CXX_aarch64_linux_android=$BIN/aarch64-linux-android24-clang++
export AR_aarch64_linux_android=$BIN/llvm-ar
export RANLIB_aarch64_linux_android=$BIN/llvm-ranlib
export CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=$BIN/aarch64-linux-android24-clang
```

Depo:

```bash
git clone --recurse-submodules https://github.com/fyildirim-debug/mailheremobile
cd mailheremobile
pnpm install                       # alt modülün app paketi (pnpm-workspace.yaml)
```

## 2. Komutlar

```bash
pnpm tauri android dev                                  # cihaz/emülatörde; arayüz Vite'tan (http://<ip>:5173)
pnpm tauri android build --apk --target aarch64 --debug # debug APK
pnpm tauri android build --apk --aab --target aarch64   # sürüm (keystore.properties varsa imzalı)
cargo run -p mailhere-android                           # kabuğu masaüstünde aç (bellek kipi; yalnız debug derlemesi)
cargo test -p mailhere-android                          # host testleri
cargo clippy --locked --target aarch64-linux-android -p mailhere-android --all-targets -- -D warnings
node scripts/kilit-denetle.mjs                          # iki Cargo.lock'ta ortak paket sürümleri aynı mı
node scripts/surum-denetle.mjs [--etiket vX.Y.Z]        # sürüm üçlüsü, alt modül sürümü, versionCode
scripts/apk-denetle.sh <apk> [--debug]                  # badging, izinler, manifest, 16 KB hizası
```

Çıktılar: `src-tauri/gen/android/app/build/outputs/apk/universal/{debug,release}/app-universal-{debug,release}.apk` (yalnız istenen ABI'yi içerir), `.../bundle/universalRelease/*.aab`. Debug APK ayıklama sembolleri taşıdığından büyüktür (~100 MB); sürüm paketi `strip` ve LTO ile küçülür.

`pnpm tauri android dev` için telefon ve bilgisayar aynı ağda olmalı; geliştirme paketinde (`src/debug/AndroidManifest.xml`) açık metin trafiği yalnız bunun için açıktır, sürüm paketinde yoktur.

- **Komutlar:** `mh_app::shared_commands![files::attachment_share, files::attachment_save, notify::notification_permission, notify::notification_settings, notify::notification_status, qr::qr_scan, bars::system_bars, arka::battery_status, arka::battery_settings, arka::background_mode_get, arka::background_mode_set, haptic::haptic, acilis::autostart_get, acilis::autostart_set]` (liste `commands.txt`, izinler `capabilities/main.json`; `lib.rs`teki test üçünü eşler). `autostart_get/set` iki kabukta aynı adla, kabuğa özgü gövdeyle tanımlıdır (masaüstünde oturum açılış kaydı); test bu ikisini `BOTH_SHELLS` listesinden tanır, öteki masaüstü komutlarına izin vermez. Ortak komutların gövdesi alt modülde (QR aktarımın `transfer_begin/cancel/receive/apply` komutları ve bildirim düğmelerinin `notify_action`/`notify_reply` komutları dahil; telefonda bildirim düğmeleri komut değil `eylem.rs` yolunu kullanır, komutlar ortak listede olduğundan izinlidir); kabuğa özgü iş `Platform` üzerinden gelir.
- **Pencere:** tek `main` penceresi `index.html#/main`; yönlendirme bekçisi (`mh_app::routes::is_app_url`) uygulama dışı adresi engeller, geliştirme sunucusuna yalnız debug derlemesinde izin verir. Hızlı okuma `mh:open`, yazma `mh:navigate { route }` (`mh_core::events::NAVIGATE`, `NavigateEvent`) olayıyla aynı pencerede açılır.
- **Veri yolları:** veritabanı `<dataDir>/files/mailhere.db` (`app_local_data_dir` + `files`), önbellek `cacheDir`. Açılan ekler `cache/ekler/<posta>/<ad>`, seçilen ekler `cache/giden/<uuid>/<ad>`.
- **Kasa:** `SecretVault.kt` — `AndroidKeyStore` AES-256-GCM (StrongBox varsa, yoksa TEE; kimlik doğrulama şartı yok), Keystore'un ürettiği 12 B IV, AAD = anahtar adı, `IV||şifre||etiket` Base64 ile `mailhere-kasa.xml` (MODE_PRIVATE). Veritabanı anahtarı `db-key` adıyla aynı kasada. Rust tarafı (`keystore.rs`) kasaya **etkinliksiz JNI köprüsünden** gider (`kopru.rs` → `ArkaKopru.kasaOku/kasaYaz/kasaSil`; işlemler Kotlin'de tek kilitle sıralanır): her IMAP bağlantısı bir okuma yapar ve bu, pencere yok edildikten sonra ya da hiç pencere açılmadan da olur. Hata metinleri değer taşımaz.
- **Etkinliksiz JNI köprüsü (`kopru.rs` ↔ `ArkaKopru.kt`):** Tauri'nin eklenti köprüsü (`run_mobile_plugin`) etkinlik ister; etkinlik yok edilmişken `first_activity_id().expect(…)` ile panikler (sürüm profili `panic = "abort"`). Çekirdeğin kendi başlattığı her iş bu yüzden eklentiden değil köprüden geçer: kasa, yeni posta bildirimi, bildirimleri uzlaştırma, eylem sonuçları (`bildirimKaldir/hata/yanitKuyrukta/yanitGeriAlindi`), bekleyen eylemler, "anlık bildirim açık mı". Köprü `MailhereApp.onCreate` (süreç başı; etkinlikli ya da etkinliksiz) içinde `ArkaKopru.kur(ctx, filesDir, cacheDir)` ile kurulur: `JavaVM`, uygulama `Context`i ve `ArkaKopru` sınıfının `GlobalRef`i saklanır (Rust iş parçacıklarının sınıf yükleyicisi uygulama sınıflarını bulamaz; sınıf hep bu `GlobalRef` üzerinden çağrılır). Her çağrı kendi yerel çerçevesinde (`with_local_frame`), iş parçacığı kalıcı bağlanır; Java istisnası günlüğe yazılıp temizlenir ve `Err` döner; hiçbir yol paniklemez. `kur` ayrıca günlüğü ve süreçteki tek tokio ortamını kurar (`tauri::async_runtime::set` süreçte yalnız bir kez çağrılabilir; sonra açılan Tauri aynı ortamı kullanır). Eklentide kalanlar yalnız arayüzden, pencere varken çağrılır: dosya seç/aç/paylaş, QR, sistem çubukları, dokunsal geri bildirim, pil, anlık bildirim anahtarı, bildirim izni/ayar sayfası. Rust girişleri `Java_com_furkanyildirim_mailhere_plugin_ArkaKopru_{kur,cekirdekBaslat,cekirdekDurdur,cekirdekDurumu,esitle,eylem,tekSefer}`; `kopru.rs` birim testi Kotlin `external fun` imzalarıyla eşler, `scripts/apk-denetle.sh` sembolleri `.so` içinde arar; R8 için `proguard-rules.pro` sınıfı korur.
- **Dosyalar:** seçici `tauri-plugin-dialog` (SAF), içerik `tauri-plugin-fs` ile `content://`dan okunur; açma `ACTION_VIEW`, paylaşma `ACTION_SEND`, ikisi de `FileProvider` (`<paket>.ekler`, yalnız `cache/ekler/`) ve dosya başına geçici okuma izniyle. Güvenli olmayan türler (`opens_directly` dışı) doğrudan açılmaz, paylaşım sayfasına verilir.
- **Bildirim:** `Platform::notify` (pencereli çekirdek) ya da `HeadlessShell::notify` (etkinliksiz çekirdek) → `notify.rs` aynı eşitlemede gelen postaları 350 ms toplar, kullanıcının düğme listesini ekler → `ArkaKopru.bildir` (JNI) → `Bildirimler.kt` (`NotificationCompat`; eklentinin kurucusu grup özeti, açık sürüm ve etkinliksiz eylem desteklemediği için kullanılmaz, yalnız izin komutları eklentiden). Kanal `yeni-posta` (HIGH, adı/açıklaması `strings.xml`); posta başına bildirim (etiket `posta:<id>`): başlık gönderen, alt metin hesap adı, gövde konu (genişletince kalın konu + önizlemenin ilk satırı; gövde ve ek adı yok), kategori `email`. Hesap başına grup `mailhere:<hesap>` ve sabit etiketli özet `ozet:<hesap>` (InboxStyle: "N yeni posta", en çok 6 satır gönderen + konu). Bir yığında yalnız en yeni posta ses çıkarır ve üstten görünür; öteki postalar ve özet sessizdir (`GROUP_ALERT_CHILDREN` + `setSilent`: çocuk `GROUP_ALERT_SUMMARY`, özet `GROUP_ALERT_CHILDREN` olur). Kilit ekranı `VISIBILITY_PRIVATE` + açık sürüm (yalnız hesap adı ve "Yeni posta" / "N yeni posta"); sistem "hassas içeriği gizle" seçiliyse o görünür. Dokununca `MainActivity` (`singleTask`, `POSTA_AC`) → `MhPlugin` bildirimi kaldırır, Rust'a `ac` olayı → `Platform::open_main` → `mh:open`; soğuk açılışta dokunuş Rust dinlemeye başlayınca alınır ve sayfa yüklendikten 1,2 s sonra açılır. Okunan, arşivlenen, silinen (başka cihazda okunan dahil) postanın bildirimi `counts_changed` → `reconcile_soon` (1,5 s birleştirme) ile kalkar, özet güncellenir; kullanıcının kapattığı özet yeniden kurulmaz. Elek'e düşen postalar `Platform::notify`a hiç gelmez (`mh_app::screener::screen` ayıklar). Android 13+ izni `notification_permission` komutuyla istenir (`granted` | `denied` | `prompt` | `promptWithRationale`; arayüz aktarım bittikten sonra çağırır). Kitaplıktan gelen `WAKE_LOCK` izni ve bildirim eklentisinin açılış alıcısı manifestte atılır; `RECEIVE_BOOT_COMPLETED` kendi açılış alıcımız ve kalıcı yoklama işi için bildirilir.
- **Bildirim eylemleri:** düğmeler kullanıcının ayarından (`Settings.notify_actions`; Ayarlar › Bildirimler; varsayılan **Yanıtla, Sil, İstenmeyen**; en çok 3, sıra korunur): Yanıtla satır içi (RemoteInput, sistem önerili yanıt kapalı), Okundu, Arşivle, Sil (çöp), İstenmeyen (hesabın `junk` kutusuna; kutu yoksa düğme gösterilmez — `mh_app::notify_actions::has_junk`), yanıt kuyruktayken Geri al. Liste `notify.rs::eylem_adlari` ile Kotlin adlarına (`yanit`, `okundu`, `arsivle`, `sil`, `istenmeyen`) çevrilir ve bildirimin eklerinde saklanır (yeniden çizimde aynı düğmeler). Düğme → `BildirimAlici` (dışa kapalı alıcı) → `ArkaKopru.eylem(json)` (JNI) → `eylem.rs::dispatch_global` → süreçte hangi çekirdek açıksa onun çalışma ortamında `mh_app::notify_actions::apply` (MarkRead/Archive/Trash/Spam) ya da `reply` (giden kutusu, "gönderimi geri al" süresi; yanıt arayüzün hızlı yanıtıyla aynı: Reply-To ya da gönderen, kendi adres çıkarılır, `Re:` konu, hesabın yanıt imzası, alıntı; gövde inmemişse 8 sn beklenir, yoksa önizleme alıntılanır). İşler önce yerelde uygulanır, sunucuya kalıcı işlem kuyruğuyla gider (ağ yoksa bağlantı gelince). Bitince bildirim kalkar ve özet güncellenir; yanıtta bildirim geri sayımlı "Geri al" satırına döner, süre bitince kendiliğinden kalkar; hata olursa bildirimde neden ve çözüm yazar (ör. "Bu hesapta İstenmeyen klasörü yok…"). Çekirdek yoksa (süreç yeni açıldı ya da hiç yok) `eylem` `false` döner: eylem `SecretVault`ta (`bildirim-bekleyen`, AES-GCM; yanıt metni taşıyabilir) en çok 50 kayıtlık kuyruğa yazılır, bildirim "Birazdan uygulanacak; olmazsa Mailhere açılınca" durumuna geçer ve alıcı hizmeti başlatmayı dener (bildirim düğmesi Android 12+'ta arka plandan ön plan hizmeti başlatmaya izin verir): hizmet etkinliksiz çekirdeği açar, `ArkaKopru.bekleyenler` ile kuyruğu boşaltır ve aynı yoldan uygular; olmazsa uygulama açılınca `eylem::setup` uygular. Pencere yokken ("ac" dışında) her eylem çalışır; dokunuş etkinliği açar.
- **Bildirim sağlığı:** `battery_status` (`unrestricted` | `optimized` | `restricted`: `PowerManager.isIgnoringBatteryOptimizations`, Android 9+ `ActivityManager.isBackgroundRestricted`), `battery_settings` ("Kısıtlı"ysa uygulama ayar sayfası, değilse `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, açılamazsa optimizasyon listesi; kullanıcı dönünce çözülür), `background_mode_get/set` (anlık bildirim; **seçilmemişse açık**; bkz. "Arka plan"). Arayüz Ayarlar › Bildirimler'de açıklamayla gösterir; masaüstünde komutlar yoktur, satırlar gizlenir.
- **Dokunsal geri bildirim:** `haptic { kind: 'tick' | 'confirm' | 'reject' }` → `View.performHapticFeedback` (API 34+ `GESTURE_THRESHOLD_ACTIVATE`, API 30+ `CONFIRM`/`REJECT`; eski sürümde `CLOCK_TICK`/`VIRTUAL_KEY`/`LONG_PRESS`); sistemin dokunma geri bildirimi ayarına uyar, `VIBRATE` izni gerekmez.
- **QR tarayıcı:** `qr_scan` → Kotlin `scanQr` → tam ekran `QrScanActivity` (`exported=false`, ekran yönü serbest, koyu tema). CameraX (`camera-core/camera2/lifecycle/view` 1.5.x) arka kamera önizlemesi + `ImageAnalysis` (~720p, yalnız en son kare); her karenin Y düzlemi parlaklık dizisine alınır, önce çerçeve kılavuzundaki orta kare sensör dönüşüne göre dik çevrilip, sonra tüm kare, düz ve ters renkle `zxing core` 3.5.x ile çözülür. İkisi Apache-2.0; ML Kit yoktur (`apk-denetle.sh` dex'te `mlkit` ve Play Hizmetleri'nin ölçüm/konum/reklam sınıflarını arar; Play Hizmetleri yalnız sunucu itmesi içindir). Yalnız `mailhere://aktar?` ile başlayan metin kabul edilir; başka QR'da kısa uyarı gösterilir, tarama sürer; bulunca titreşimsiz kapanır. Sözleşme: `qr_scan() → string | null` (vazgeçince `null`; masaüstü geliştirme ikilisinde her zaman `null`, arayüz kodu yapıştırmaya düşer). Kamera izni çalışma anında, yalnız bu ekranda istenir; reddedilirse "Kamera izni verilmedi; Ayarlar'dan izin ver ya da kodu yapıştır." hatası, kamera açılamazsa "Kamera açılamadı…" hatası döner. Ekran metinleri `res/values/strings.xml` (Türkçe) ve `values-en` (İngilizce); renkler koyu temanın jetonları (`#0F1115` zemin, `#22252D` kart, `#E6E8ED` yazı, `#8C96F6` vurgu); yazı tipi sistem yazı tipidir (Geist yalnız web arayüzünde, alt modülde ttf yok). Üst çubuk 56 dp, düğmeler 48 dp, yazı 15 sp.
- **Günlük:** `tracing-android` → logcat etiketi `Mailhere`; protokol kitaplıklarının ayrıntılı günlüğü ortak süzgeçle kapalıdır. `adb logcat -s Mailhere`.
- **Manifest:** izinler yalnız `INTERNET`, `POST_NOTIFICATIONS`, `CAMERA`, `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` (anlık bildirim hizmeti), `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (kullanıcı açıklamayı okuyup dokununca), `RECEIVE_BOOT_COMPLETED` (açılışta hizmet; kalıcı yoklama işi `setPersisted` bunu şart koşar) (+ `uses-feature android.hardware.camera required=false`: kamerasız cihazda kurulur, kod yapıştırılır; bir de androidx.core'un her uygulamada tanımladığı, uygulamaya özel imza düzeyi `<paket>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`; sistem izni değildir). `WAKE_LOCK` yok (hizmet ve iş kendi uyanıklığını taşır). Bileşenler: `MailhereApp` (uygulama sınıfı; köprüyü kurar), `MainActivity` (`singleTask`), `QrScanActivity` (dışa kapalı), `YenidenBaslatActivity` (dışa kapalı, ayrı süreç `:yeniden`, saydam, son uygulamalarda görünmez), `FileProvider`, `BildirimAlici` (dışa kapalı), `BootAlici` (`exported=true`, yalnız `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` sistem yayınları), `ArkaPlanIsi` (`BIND_JOB_SERVICE`), `ArkaPlanHizmeti` (dışa kapalı, `specialUse`, `stopWithTask=false`); `allowBackup=false`, `fullBackupContent=false`, `dataExtractionRules` tümünü dışlar; açılış zemini `#ECEEF2` / gece `#0F1115`. Geliştirme paketi (`--debug`, `pnpm tauri android dev`) yalnız Vite sunucusu için `usesCleartextTraffic=true` taşır (`src/debug/AndroidManifest.xml`); sürüm paketinde yoktur.

### Arka plan: Tauri yaşam döngüsü ve anlık bildirim

Araştırma (Tauri 2.12.3, tao 0.37.1, wry 0.57.0 kaynakları; `gen/android/.../generated/*.kt`):

1. **Başlatma süreç başına bir kez.** `WryActivity.onCreate` `ProcessLifecycleOwner`a `WryLifecycleObserver` ekler; onun `onCreate`i (süreçte bir kez) `Rust.onFirstActivityCreate` → tao `ndk_glue::onFirstActivityCreate` → ayrı iş parçacığında `run()`. `setup` (çekirdek, eşitleyiciler, eklenti kaydı) süreç başına bir kez çalışır; etkinlik yeniden yaratılınca tekrar çalışmaz (çift başlatma yok). Yapılandırma değişikliğinde (döndürme vb.) tao/wry pencere ve webview'u korur.
2. **Etkinlik arka planda (Ana ekran, başka uygulama, Android 12+ kökte geri).** `onPause/onStop` yalnız `Suspended/Stopped` olayı üretir; tokio çalışma ortamı (`mh_app::logging::runtime`, ayrı iş parçacıkları), IMAP IDLE, JMAP EventSource, `AppHandle`, eklenti tutamaçları yaşar, bildirim üretilebilir. Ön plan hizmeti yoksa süreç "önbellekte" sayılır: Android 11+ önbellek dondurucusu süreci kısa sürede dondurur (iş parçacıkları durur, IDLE akmaz), üretici uyutucuları ve bellek baskısı süreci öldürür.
3. **Etkinlik yok edilince (Android ≤ 11'de kökte geri, son uygulamalardan kaydırma, `finish`).** tao `WindowEvent::Destroyed` → tauri-runtime-wry pencereyi siler; pencere kalmayınca `RunEvent::ExitRequested { code: None }`, engellenmezse `ControlFlow::Exit` → `std::process::exit`. Çıkış engellenirse süreç, tokio ortamı, `AppHandle`, zamanlayıcılar ve IDLE bağlantıları yaşar; ama wry `onWebviewDestroy` etkinlik vekilini siler ve sonraki her `run_mobile_plugin` (eklenti köprüsü) `dispatch`te `first_activity_id().expect("no available activity")` ile panikler (sürüm profili `panic = "abort"`). Bu yüzden çekirdeğin kendi başlattığı işler eklentiden değil etkinliksiz JNI köprüsünden geçer (v0.7). `setup` yeniden çalışmadığından aynı süreçte yeni etkinlikte webview kurulmaz (boş ekran); yeniden açılış süreci temiz başlatır (trampolin).
4. **Etkinliksiz başlatma (açılış alıcısı, hizmet, JobScheduler, bildirim düğmesi).** Tauri'nin `setup`ı etkinlik ister (`register_android_plugin`, `create_main` → `NoAvailableActivity`); `Rust.onFirstActivityCreate` yalnız etkinlikle gelir. `mh_app::state::Core` ise Tauri'siz kurulabilir: v0.7'de `mh_app::headless::Headless` bunu yapar, kasa ve bildirim JNI köprüsünden geçer, etkinlik açılınca `setup_core`dan önce kapatılır (süreç başına tek çekirdek; çift eşitleme yok).

## 6. Cihaz denetim listesi

Bu ortamda cihaz/emülatör çalıştırılamadığından aşağıdakiler gerçek cihazda doğrulanır (her sürümde, en az Android 7 ve Android 14+ birer cihaz):

1. **Açılış:** ilk açılışta beyaz parlama yok (açık/koyu tema zemin rengi); arayüz yüklenir; `adb logcat -s Mailhere` "veri klasörü" satırını gösterir.
2. **Kasa:** hesap ekle → uygulamayı kapat/aç → parola sorulmadan eşitlenir (`mailhere-kasa.xml` var, düz metin içermez). Hesabı kaldır → kayıt silinir. StrongBox'lı ve StrongBox'sız cihazda anahtar üretimi.
3. **Veritabanı:** `files/mailhere.db` SQLCipher ile şifreli (`strings` ile okunamaz); uygulama verisi `adb backup` ile çıkmaz (`allowBackup=false`).
4. **Bildirim:** Android 13+'ta izin isteği (`notification_permission`); yeni postada kanal `yeni-posta` bildirimi (simge zarf, renk vurgu); başlık gönderen, alt metin hesap, gövde konu, genişletince önizlemenin ilk satırı; aynı anda 3 posta → tek ses, en yenisi üstten görünür, hesap özeti "3 yeni posta"; iki hesap → iki grup; dokununca ilgili posta açılır (`mh:open`; uygulama kapalıyken de, sayfa yüklenince) ve bildirim kalkar; postayı uygulamada ya da bilgisayarda okuyunca bildirim birkaç saniyede kalkar, özet sayısı düşer; kilit ekranında "hassas içeriği gizle" açıkken yalnız hesap adı ve "Yeni posta"; Elek'e düşen göndericiden bildirim gelmez; sessize alma ve hesap başına bildirim kapatma çalışır.
4a. **Bildirim düğmeleri:** varsayılan sırayla **Yanıtla, Sil, İstenmeyen** görünür (en çok üç); Ayarlar › Bildirimler'de düğmeleri değiştirip sırala (ör. Okundu, Arşivle, Yanıtla) → yeni bildirimde aynı sıra; İstenmeyen klasörü olmayan hesapta (ör. yalnız INBOX) İstenmeyen düğmesi görünmez. Okundu → bildirim kalkar, posta okunmuş (bilgisayarda da); Arşivle → posta Arşiv'de; **Sil → posta Çöp'te** (bilgisayarda da); **İstenmeyen → posta İstenmeyen klasöründe**; uçak kipinde Sil → bildirim kalkar, bağlantı gelince sunucuda uygulanır; satır içi Yanıtla → geri sayımlı "Geri al" satırı, süre bitince yanıt Gönderilenler'de (konu `Re:`, alıntı, imza); Geri al → "Yanıt geri alındı"; hata (ör. kutu yok) → bildirimde neden ve çözüm, bildirim yerinde. Wear OS / Android Auto'da eylemler görünür.
4b. **Anlık bildirim — varsayılan ve ekranda:** ilk kurulumda Ayarlar › Bildirimler › "Anlık bildirim" açık; bildirim izni verilince bildirim panelinin en altında katlı, sessiz "Anlık bildirim açık" (kanal "Arka plan bağlantısı", `arka-plan-sessiz`); **durum çubuğunda Mailhere simgesi yok**, kilit ekranında görünmez; Ayarlar › Uygulamalar › Mailhere › Bildirimler'de eski "Arka plan bağlantısı" kanalı ikinci kez görünmez (0.7.x'ten güncellemede eski kanal silinir); Ana ekran tuşu + ekran kapalı 30 dk → başka cihazdan gönderilen posta saniyeler içinde bildirilir (`adb shell dumpsys deviceidle force-idle` ile Doze'da da); Android 14/15/16'da `adb shell dumpsys activity services com.furkanyildirim.mailhere` türü `specialUse` gösterir; anahtar kapat → hizmet durur, bildirim kalkar; yeniden aç → geri gelir.
4e. **Kaydırma sonrası (süreç yaşar):** anlık bildirim açıkken uygulamayı son uygulamalardan kaydır → "Anlık bildirim açık" bildirimi **kalır**, `adb shell pidof com.furkanyildirim.mailhere` aynı pid; logcat'te "pencere kapandı; anlık bildirim açık, çekirdek arka planda sürüyor"; başka cihazdan posta gönder → saniyeler içinde bildirim (grup, özet, düğmeler aynı); bildirimde **Sil / İstenmeyen / Yanıtla** → uygulama açılmadan uygulanır, bildirim kalkar / geri sayım; bildirime dokun → uygulama **temiz açılır** (kısa açılış; `pidof` yeni pid; `dumpsys activity activities` tek görev) ve posta açılır; uygulama simgesinden aç → aynı şekilde yeni süreç, gelen kutusu; döndürme ve "Geliştirici › Etkinlikleri tutma" ile de boş ekran yok.
4f. **Yeniden başlatma sonrası (etkinliksiz çekirdek):** telefonu yeniden başlat, uygulamayı **açma** → 1–2 dk içinde "Anlık bildirim açık" bildirimi gelir (BootAlici → hizmet), logcat "etkinliksiz çekirdek çalışıyor"; başka cihazdan posta → bildirim; Sil / İstenmeyen / Yanıtla uygulama açılmadan çalışır; Geri al çalışır; sonra uygulamayı aç → logcat "etkinlik geldi; etkinliksiz çekirdek pencereliye yer açıyor", liste güncel, çift bildirim yok, `mailhere.db` bozulmamış. Android 15+ cihazda hizmet açılıştan başlıyor mu (specialUse) ayrıca doğrula; başlamazsa "Arka plan bağlantısı kurulamadı" bildirimi görünmeli ve 15 dk içinde yoklama işi (`adb shell dumpsys jobscheduler | grep mailhere`) posta bildirmeli.
4g. **Anlık bildirim kapalı + yoklama:** anahtarı kapat, uygulamayı kaydır → süreç çıkar (`pidof` boş); başka cihazdan posta → en geç ~15–20 dk içinde bildirim (iş; `adb shell cmd jobscheduler run -f com.furkanyildirim.mailhere 7` ile hemen tetiklenebilir); bildirimden Sil → "Birazdan uygulanacak…" sonra hizmet açılamazsa uygulama açılınca uygulanır; uçak kipinde iş hiç çalışmaz (ağ şartı). Bildirim izni kapalıyken iş hiçbir şey yapmaz; hesap yokken çekirdek hemen kapanır (logcat "hesap yok").
4i. **Açılışta başlat (Genel):** ilk kurulumda Ayarlar › Genel › Başlangıç › "Açılışta başlat" açık, açıklama "Telefon açılınca Mailhere arka planda başlar ve postaları denetler."; telefonu yeniden başlat, uygulamayı açma → durum çubuğunda Mailhere simgesi **yok**, panelin altında katlı "Anlık bildirim açık" satırı var; başka cihazdan posta → saniyeler içinde yeni posta bildirimi (o da durum çubuğunda zarf simgesiyle). Anahtarı kapat → yeniden başlat → `adb shell dumpsys activity services com.furkanyildirim.mailhere` hizmet yok, panelde satır yok, logcat'te "etkinliksiz çekirdek" yok; 15–20 dk içinde yoklama işi çalışırsa hizmet **kurulmaz** (yalnız tek seferlik eşitleme; `adb shell cmd jobscheduler run -f com.furkanyildirim.mailhere 7`); uygulamayı aç → anlık bildirim her zamanki gibi başlar. Anahtarı yeniden aç → sonraki açılışta hizmet gelir. Güncelleme kurulumu (`adb install -r`) bayrak kapalıyken de anlık bildirimi geri kurar. Android 8.0/8.1 cihazda sistemin ek "arka planda çalışıyor" satırı çıkıyor mu not edilir.
4i. **Parola kilidi — açılış:** Ayarlar › Gizlilik ve güvenlik › "Kilidi kur" (parola iki kez, onay kutusu) → uygulamayı kaydır ve yeniden aç → kilit ekranı (menü, liste, yüzen düğme yok; alan odakta, 48 px düğme); yanlış parola → "Parola yanlış. Yeniden dene."; 6. yanlıştan sonra "N saniye sonra" sayacı; doğru parola → liste gelir, logcat "kilit açıldı; çekirdek başladı"; başka cihazdan posta → bildirim.
4j. **Parola kilidi — yeniden başlatma:** telefonu yeniden başlat, uygulamayı açma → "Anlık bildirim açık" ile birlikte sessiz **"Mailhere kilitli"** bildirimi (kanal "Parola kilidi"), logcat "etkinliksiz çekirdek: parola kilidi açık, çekirdek açılmadı"; başka cihazdan posta → **bildirim gelmez** (çekirdek kapalı); `adb shell cmd jobscheduler run -f com.furkanyildirim.mailhere 7` → iş hemen biter (kod 7), bildirim yinelenmez (ses yok); bildirime dokun → uygulama kilit ekranıyla açılır → parola → "Mailhere kilitli" bildirimi kalkar, posta iner ve bildirimler gelir; kaydır → süreç yaşar, bildirimler sürer (anahtar bellekte).
4k. **Parola kilidi — dönüşte yeniden kilit ve unutma:** Ana ekran tuşu, 1 dk bekle, uygulamaya dön → kilit ekranı ("Uygulamaya dönüldü…"), bu arada gelen posta bildirimi normal içerikli; parola → liste. Ayarda "Uygulamaya dönünce parola sor" kapalıyken dönüşte kilit yok. Kilit ekranında "Parolamı unuttum" → uyarı → onay: açılışta kilitliyse hesap ekleme ekranı gelir; çekirdek açıkken süreç kapanır, yeniden açınca `files/sifirla.json` uygulanır (veritabanı, kasa kayıtları `db-key-kilitli` ve hesap parolaları silinir) ve hesap ekleme ekranı gelir. "Kilidi kapat" mevcut parolayı ister; sonra yeniden başlatmada parola sorulmaz.
4h. **Kapat düğmesi etkinliksizken:** kaydırılmış ya da yeniden başlatılmış durumda bildirimdeki "Kapat" → hizmet ve çekirdek durur, süreç biter (`pidof` boş), anahtar kapalı kalır; uygulamayı aç → anahtar kapalı görünür.
4c. **Pil kısıtlaması:** varsayılan "Kısıtlamayı kaldır" → Android'in onay penceresi → "Yok"; pil kullanımı "Kısıtlı" iken uygulama ayar sayfası açılır, "Kısıtlamasız" seçip dönünce satır güncellenir.
4d. **Dokunsal geri bildirim:** kaydırma eşiğinde hafif tık, onayda/redde farklı titreşim; sistem "dokunma geri bildirimi" kapalıyken titremez.
5. **Ekler:** eki aç (PDF/resim uygun uygulamada, FileProvider adresi `content://com.furkanyildirim.mailhere.ekler/ekler/...`); güvenli olmayan tür paylaşım sayfasına düşer; "Paylaş" (`attachment_share`) ve "Kaydet" (`attachment_save`, SAF) çalışır; ek eklerken seçilen dosya önbelleğe kopyalanır ve gönderilen postada adı/içeriği doğru gider.
6. **Yazma ve okuma:** `open_compose` → `mh:navigate` ile yazma yığını açılır; `.eml` kaydetme SAF ile; takvim daveti `.ics` takvim uygulamasında açılır.
7. **Sertifika onayı:** kendinden imzalı sunucuda onay iletişim kutusu (ebeveynsiz `confirm`) görünür, ret/onay doğru işler.
8. **Açılış hatası:** kasa erişilemez durumdayken (örn. test için kasa kaydı bozulmuş) hata iletişim kutusu gösterilir, "Kapat" uygulamayı kapatır; dosya silinmez.
9. **OAuth:** Google/Microsoft girişi tarayıcıda açılır, `127.0.0.1` dönüşü uygulamaya gelir (cihazda doğrulanmalı).
10. **Ağ:** uçak kipi → kapat → eşitleme kendiliğinden toparlar; IDLE/JMAP anlık bildirim arka planda kesilince yeniden kurulur (anlık bildirim açıkken, pencereli ve etkinliksiz çekirdekte; kapalıyken süreç dondurulabilir, uygulama açılınca ya da yoklama işinde toparlar).
11. **Geri tuşu:** mobil arayüz geldiğinde çekmece/alt sayfa/yığın sırası; kökte uygulama arka plana gider (Android 7–11'de de; süreç ve anlık bildirim yaşar).
12. **Performans:** 10 bin postalı hesapta liste kaydırması akıcı; soğuk açılış < 2 s (orta sınıf cihaz).
13. **16 KB sayfa:** Android 15+ 16 KB cihaz/emülatörde kurulup açılır (`scripts/apk-denetle.sh` hizayı doğrular).
14. **Güncelleme:** önceki sürümün üstüne kurulum veriyi korur; `versionCode` artmış olmalı.
15. **QR aktarım — izin:** "Bilgisayardan al" ilk kez açılınca kamera izni sorulur; reddedilince "Kamera izni verilmedi; Ayarlar'dan izin ver ya da kodu yapıştır." görünür ve kod yapıştırma yolu çalışır; "Bir daha sorma" sonrasında sistem iletişim kutusu çıkmadan aynı hata gelir. Kamerasız cihaz/emülatörde "Kamera açılamadı…" hatası ve yapıştırma yolu.
16. **QR aktarım — tarayıcı:** koyu tam ekran, önizleme akıcı, çerçeve kılavuzu ortada, sistem çubukları saydam (çentik/geçişli ekranda üst çubuk güvenli alanda); geri düğmesi ve sistem geri tuşu `null` ile kapatır; fener düğmesi yalnız flaşlı cihazda görünür, açınca vurgu rengine döner, ekran kapanınca söner; döndürünce ekran yeniden oluşturulmaz ve okuma sürer; başka bir QR'da (ör. web adresi) "Bu bir Mailhere aktarım kodu değil" 1,8 s görünür, tarama devam eder; masaüstündeki QR ters (koyu tema) gösterilirken de okunur.
17. **QR aktarım — uçtan uca:** bilgisayarda Ayarlar › Cihazlar › "Telefona aktar" → telefonda QR okut → özet (hesaplar, kurallar, etiketler, ayarlar) → uygula → bilgisayarda "uygulandı" durumu → telefonda bildirim izni isteği (13+) → gelen kutusu eşitlenir; parolasız hesap raporda listelenir. Aynı Wi-Fi'de değilken (hücresel veri) 30 s içinde anlaşılır ağ hatası; kodu yapıştırarak alma aynı sonucu verir; 3 dk sonra süresi dolan kod reddedilir.

## 7. Bilinen sınırlar (Aşama 4d)

- Arayüzün `qr_scan`, `notification_permission`, `attachment_share`, `attachment_save` komutlarını sözleşmeye (`app/src/lib/api/types.ts`) ve sahte arka uca eklemesi ile "Bilgisayardan al" ekranının tarayıcıyı çağırması alt modülün Aşama 4c işidir; kabuk tarafı hazırdır.
- Telefondan bilgisayara aktarım (telefonda `transfer_begin`) henüz arayüzde yok; komut ortak listede olduğundan izinlidir.
- Anlık bildirim kapalıyken uygulama arka planda dondurulabilir; yeni posta en geç yoklama işinde (~15 dk, ağ varken) bildirilir. Açıkken kaydırma ve yeniden başlatma bağlantıyı kesmez; Android 12+ yalnız izinli yollardan (açılış, bildirim düğmesi, ekran) hizmet başlatır — alarm ve iş başlatamaz, o durumda yoklama yedektir.
- Etkinliksiz çekirdekte yanıt hatırlatmalarının zamanlayıcısı ve ertelemelerin geri dönüşü çalışmaz (pencereli çekirdek açılınca, kaydırma sonrası yaşayan pencereli çekirdekte de çalışır); kurallar, elek, sessiz saat, VIP ve susturma aynıdır (susturma süreç belleğindedir).
- Çekirdek yokken basılan bildirim düğmesi hizmet başlatılamazsa uygulama açılınca uygulanır; o arada başka cihazdan yapılan değişiklikle çakışırsa son işlem geçerlidir. "Geri al" o durumda geç kalabilir (giden kutusu açılışta hemen gönderir); bildirim sonucu söyler.
- Kaydırmadan sonra yeniden açma süreci yeniden başlatır (trampolin); açılış birkaç yüz ms uzar ve arayüz durumu (açık posta, kaydırma yeri) sıfırlanır.
- Hizmet açılışta başlatılamayan cihazlarda (üretici kısıtı, Android 15 kuralları değişirse) "Arka plan bağlantısı kurulamadı" bildirimi görünür; yoklama 15 dk'da birdir.
- Bildirim metinleri (kanal adları, düğmeler, özet) telefonun dilini izler (`strings.xml`); arayüzün dil ayarını değil.
- Parola kilidi açıkken telefon yeniden başladıktan sonra kullanıcı uygulamayı bir kez açıp parolayı girmeden posta gelmez ve bildirim üretilmez (anahtar yalnız parolayla açılır); "Mailhere kilitli" bildirimi bunu söyler. Kilit açıldıktan sonra süreç yaşadığı sürece arka plan v0.7 ile aynıdır; süreç ölürse (bellek baskısı, hizmetin yeniden kurulması) yine kilitli bildirim gelir. Yanlış parola sayacı süreç belleğindedir.
- Ön plan hizmetinin bildirimi tamamen gizlenemez (Android kuralı): en düşük önemli kanalda panelin altında katlı durur, durum çubuğunda simge göstermez. Kullanıcı kanalı sistem ayarından kapatabilir; hizmet yine çalışır.
- "Açılışta başlat" kapalıyken açılış yayını süreci yine kısa süre açar (alıcı bildirilmiştir; bileşen kapatılmaz ki güncelleme yayını çalışsın), ama hiçbir hizmet ya da çekirdek başlatılmaz.
